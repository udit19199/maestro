Lesson 1: Swift & SwiftUI Basics through Zoro's Eyes

Welcome! If you are new to Apple's ecosystem, the code in Zoro might look a bit unfamiliar at first. Don't worry! Swift is an elegant, modern language, and SwiftUI makes building user interfaces incredibly straightforward once you understand a few key patterns.

In this lesson, we will cover the core grammar of Swift and the declarative mental model of SwiftUI, using Zoro's actual source code as our guide.

1. Swift Foundations: Variables & Constants

In Swift, you define data using either let or var:

  • let defines a constant (a value that can never change once set).
  • var defines a variable (a value that can be modified later).

Let's look at a snippet from Zoro's ClarifyTool.swift:

struct ClarifyTool: Tool {
    let name = "clarify" // Constant: This tool's identifier is always "clarify"
    
    @Generable
    struct Arguments {
        var question: String // Variable: The question will change per execution
    }
}

2. Optionals: Handling Missing Data

One of Swift's most famous features is safety. By default, variables cannot be empty (or nil). If a variable is allowed to have no value, you must explicitly mark it with a question mark (?). This is called an Optional.

In Zoro's WorkspaceManager.swift, the selected workspace path is optional because when the app first launches, no folder has been selected yet:

var workspaceURL: URL? = nil // '?' means it can hold a URL OR be nil

Before you can use an optional's value, you must "unwrap" it safely. Zoro frequently uses the guard let statement for this:

guard let workspaceURL = WorkspaceManager.shared.workspaceURL else {
    return "Error: No workspace directory selected." 
}
// If workspaceURL was nil, the function exits early above.
// Otherwise, workspaceURL is now safely unwrapped and ready to use below!

3. Structs (Value) vs. Classes (Reference)

Swift uses both structs and classes to group data and behavior. However, they manage memory differently:

  • Structs are copied when passed around. They are lightweight and ideal for data containers. In Zoro, all tools and chat messages are structs (e.g., struct ChatMessage).
  • Classes are shared references. Multiple parts of your app can point to and edit the same class instance. Zoro's WorkspaceManager is a class because we want the exact same state holder shared across the UI and all tool executions.

4. Declarative UI: How SwiftUI Updates

In older frameworks, you had to write step-by-step instructions to change the UI (e.g., "Find the text field, change its text, change its color to red"). SwiftUI is declarative: you describe how the view should look based on the current state. When state changes, SwiftUI automatically updates the screen.

To do this, SwiftUI uses property wrappers (variables starting with @):

  • @Published: Tells SwiftUI to watch this variable. When it changes, tell the views.
  • @StateObject: Creates and keeps a shared manager class (like WorkspaceManager) alive inside a View.

The Zoro Connection: In views like ChatView.swift and SettingsView.swift, the UI holds @ObservedObject private var workspace = WorkspaceManager.shared. Inside WorkspaceManager, the list of tasks is @Published var activeTodos: [TodoItem] = []. Because of this, the moment an LLM adds a task to the todo list in the background, the UI instantly redraws to display it!
