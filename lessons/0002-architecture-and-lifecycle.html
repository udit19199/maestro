Lesson 2: Zoro Architecture & Request Lifecycle

Welcome! Now that you have the basic Swift and SwiftUI mental model down, we will explore the high-level architecture of Zoro and trace exactly what happens when you type a prompt and press Send.

The Three Core Layers

Zoro is structured around a clean, single-view SwiftUI design. It relies on three primary files to manage everything from UI rendering to LLM execution and system access:

  1. The View Layer (ContentView.swift): This is a single SwiftUI view containing the chat interface, settings panel, and configuration toggles. It listens to the state manager for updates and triggers the AI agent when a user sends a message.
  2. The State Manager (WorkspaceManager.swift): A singleton class accessible via WorkspaceManager.shared. It lives on the @MainActor (main thread) and holds all active state: the selected workspace path, active todos, active processes, and background task logs.
  3. The System Bridge / Tools Layer (*Tool.swift): A collection of files defining individual capabilities (like reading files, executing terminal commands, or searching the web). Each tool conforms to the Tool protocol from Apple's FoundationModels library.

Visualizing the Prompt Lifecycle

How does Zoro go from a raw user prompt to writing a file or running a terminal command? Here is the lifecycle of a single request:

1. Submission
The user submits a message in the text input. ContentView.triggerAgent() is invoked.
2. Session Setup
Zoro lazily loads the LanguageModelSession using the chosen backend (Apple Intelligence, Claude, local Qwen, or Mock).
3. Model Request
The session sends the prompt, conversation history, system instructions, and registered tools to the LLM.
4. Tool Execution Loop
If the LLM responds with a tool call, Zoro executes the tool's call(arguments:) method. The tool returns a String result to the LLM. This repeats if the LLM calls multiple tools.
5. Streaming & Completion
The LLM streams its final written response to the screen, updating the chat UI dynamically, and sets the loading state to false.
