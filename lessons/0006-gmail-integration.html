Lesson 6: Gmail Integration

Gmail is a first-class integration in Zoro — not an afterthought tool. This lesson explains how OAuth, the API client, UI state, and agent instructions work together to reduce hallucinations and incomplete email fetches.

Why Gmail Is Different From Other Tools

Most Zoro tools (files, shell, notes) operate on local data you control. Gmail requires:

  • OAuth — the user authorizes Zoro to access their mailbox.
  • Network pagination — search results may span many API pages.
  • Index vs body — Gmail's list/search APIs return snippets, not full email text.
The #1 hallucination risk: the LLM summarizes email from snippet fields without calling read_message or read_thread. Zoro's design explicitly separates these steps.

OAuth Flow (Connect Gmail)

1. User enters Client ID + Secret
Saved to Keychain via KeychainHelper (same pattern as Anthropic/Tavily keys).
2. Connect Gmail starts local server on port 8765
OAuthCallbackServer listens for Google's redirect with the authorization code.
3. Browser opens Google consent
User approves scopes: readonly, send, modify.
4. Tokens stored, inbox synced
Refresh token in Keychain; GmailManager.refreshSnapshot() loads unread count and preview.

Setup details: see reference/gmail-setup.md.

The Fetch Report Pattern

Every manage_gmail call returns a structured header:

=== GMAIL FETCH REPORT ===
action: search_messages
result_size_estimate: 47
items_fetched: 47
fetch_complete: true
next_page_token: none
warnings:
  - Results are an INDEX with snippets only.
  - You MUST call read_message before summarizing...
=== END REPORT ===

This gives the LLM explicit signals about completeness — it cannot plausibly claim "I fetched all 47 emails" when fetch_complete: false.

Agent Instructions Injection

When Gmail is connected, WorkspaceManager.makeSession() appends live context from GmailManager.contextualInstructions():

  • Connected email address and unread count
  • Mandatory rules: never invent IDs, always read before summarizing, cite message IDs

Sessions are invalidated (invalidateSessionsForConfigChange()) when Gmail connects or disconnects so new instructions take effect.

UI: First-Class Visibility

  • Header badge — email, unread count, sync time, manual refresh
  • Inbox preview panel — latest messages (ground truth you can eyeball)
  • Gmail activity log — what the agent fetched during the current prompt

Swift Concepts Used

  • @MainActor class GmailManager: ObservableObject — UI-bound state on the main thread
  • async/await + URLSession — Gmail API calls without blocking UI
  • withCheckedThrowingContinuation — OAuth callback server bridges socket code to async
  • SecurityPolicy limits — max messages per fetch, body bytes, retry count

Retrieval Practice

Question: A user asks "Summarize my latest email from Alice." What is the correct tool sequence?

Answer:

  1. search_messages with query from:alice (returns index with message ID)
  2. read_message or read_thread using the ID from step 1
  3. Summarize only from the full body in step 2 — never from the snippet
