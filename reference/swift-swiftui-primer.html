Swift & SwiftUI: Zoro Developer Primer

A quick-reference guide tailored specifically to code patterns inside the Zoro workspace.

This reference card breaks down the essential language features and UI components you will see throughout Zoro. Refer back to it whenever you encounter unfamiliar Swift syntax.

1. Swift Language Essentials

Structs vs. Classes

Swift uses both structs and classes, but they behave differently:

Structs (Value Types)

Copied when passed around. Perfect for simple data models and immutable tools.
Examples: ChatMessage, TodoItem, and all Tool implementations.

Classes (Reference Types)

Shared in memory. Multiple variables point to the exact same instance.
Examples: WorkspaceManager (where shared state must update globally).

Optionals (?)

In Swift, variables cannot normally be empty or nil. If a value is allowed to be missing, it is marked with a question mark (?) and called an Optional.

// Can be a URL folder path, or nil (nothing)
var workspaceURL: URL? = nil

To safely use optionals, we "unwrap" them using a guard let statement:

guard let unwrappedURL = workspaceURL else {
    return "Error: No workspace directory selected." // Exits early if nil
}
// Now 'unwrappedURL' is a regular, safe URL we can use below

Singletons (shared)

A singleton ensures that only a single instance of a class ever exists. Zoro uses this to manage active workspace files, background processes, and user tasks from anywhere in the codebase.

class WorkspaceManager {
    static let shared = WorkspaceManager() // The single global instance
    private init() {}                      // Prevents creating other copies
}

// Accessed anywhere in Zoro via:
WorkspaceManager.shared.runCommand("ls")

2. SwiftUI & State Management

SwiftUI is a declarative framework. Instead of writing code to manually add, move, or delete views, you describe how the view should look based on the current state. When state variables change, SwiftUI automatically redraws the affected views.

Property Wrappers

Property wrappers add special behavior to variables, usually starting with an @ symbol:

  • @Published: Inside a class, this tells SwiftUI to monitor this variable. If it changes, any view watching this class will automatically redraw.
  • @StateObject: Creates and manages a reference-type state class inside a view, keeping it alive during view redraws.
  • @State: Manages simple, local state (like whether a settings window is open) within a single view.
Zoro Code Pattern Connection

In ContentView.swift, you will see:
@StateObject private var workspace = WorkspaceManager.shared
Because `workspace` is a `@StateObject` and its properties like `workspaceURL` or `activeTodos` are marked `@Published` in `WorkspaceManager`, the chat UI instantly refreshes the folder path or task checklists whenever they change in the background!

3. Swift Concurrency (async/await)

Zoro needs to perform long-running tasks—like executing terminal commands, fetching data from Tavily, or waiting for Apple Intelligence—without freezing the macOS app window. It uses Swift's modern concurrency model:

  • async: Marks a function that runs in the background and can pause itself if needed.
  • await: Used when calling an async function. It indicates that the current execution will wait for the background task to complete before continuing.
  • @MainActor: A decorator indicating that a class or method must run on the main thread, which is required for any operation modifying the UI.
// Runs in the background (async) and can throw errors
func runCommand(_ command: String) async throws -> String {
    // ... execution code ...
    try process.run()
    // ...
}
